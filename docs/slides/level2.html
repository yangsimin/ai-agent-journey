为什么我们需要 RAG？

纯语言模型的痛点

  • 幻觉问题 (Hallucination)，容易一本正经地胡说八道
  • 数据滞后，无法获取最新的内部知识或实时数据
  • 无法接触企业/个人的私密文档

RAG 的解决方案

  • Retrieval (检索): 先在私有数据库中找到最相关的事实片段
  • Augmented (增强): 将事实拼接进 Prompt 上下文
  • Generation (生成): 基于给定事实让 LLM 进行阅读理解与归纳

核心概念揭秘

Chunking

文本切块：将长篇文档按照段落、句子甚至特定字数（如 500字/块）切割成极小的片段，方便局部匹配。

Embedding

向量化：利用 Embedding 模型（如 `text-embedding-004`），将一段文字转化为一串长长的浮点数数组（如 768 维降维坐标），捕获其深层语义。

Vector Store

向量数据库：专门用来存储这些向量数组。通过计算“余弦相似度 (Cosine Similarity)”，从海量数据中瞬间找出语义最相近的 Chunk。
