Function Calling 是什么？

Level 1-2：AI 只会"说"

深圳今天天气怎么样？
根据我的训练数据，深圳一般气候温暖...
可能过时、可能幻觉、无法执行操作

Level 3：AI 能"做"

深圳今天天气怎么样？
get_weather(city: "深圳")
执行结果: { temperature: 25, condition: "晴" }
深圳今天晴，气温25度，适合出门。

核心本质：两轮协议

1
你的代码 发送问题 + 工具定义

"这是用户的问题，你有这些函数可以调用：get_weather、create_todo"

2
大模型 返回结构化调用请求

"我需要调用 get_weather(city="深圳")，请帮我执行"

finish_reason 变为 "tool_calls"，content 为 null

3
你的代码 本地执行函数，拿到结果

调用 API / 查数据库 / 写文件... 得到 { temperature: 25, condition: "晴" }

4
大模型 基于结果生成自然语言回答

"深圳今天晴天，气温25度，适合出行！"

模型从不直接执行代码 — 它只告诉你"该调什么、参数是什么"

定义工具：JSON Schema

通过 tools 参数告诉模型可用函数，模型靠 description 判断何时调用。

name — 函数名，模型通过它引用函数
description — 最重要的字段，决定模型是否选择此工具
parameters — JSON Schema，定义参数结构和类型
required — 声明必填参数列表
工具数量建议不超过 20 个，超过 10 个时模型准确率开始下降。
// 原始 JSON Schema (协议层) { "type": "function", "function": { "name": "get_weather", "description": "获取城市天气...", "parameters": { "type": "object", "properties": { "city": { "type": "string" }, "unit": { "enum": ["celsius"] } }, "required": ["city"] } } } // Vercel AI SDK (Zod 风格) tool({ description: "获取城市天气...", inputSchema: z.object({ city: z.string(), unit: z.enum(["celsius"]), }), execute: async ({ city }) => ({ temperature: 25, condition: "晴" }), })

模型的响应：Tool Call

// 模型决定调用工具时的响应 { "choices": [{ "finish_reason": "tool_calls", // 关键信号！ "message": { "role": "assistant", "content": null, // 不生成文本 "tool_calls": [{ "id": "call_abc123", // 唯一 ID，回传时必须匹配 "function": { "name": "get_weather", "arguments": "{\"city\":\"深圳\"}" // JSON 字符串！需 parse } }] } }] }
tool_calls
finish_reason 变为此值
content: null
模型不生成任何文本
tool_call_id
回传结果时必须严格匹配

高级特性

并行调用 — 模型一次可返回多个 tool_calls，并行执行减少延迟
多步推理 — 收到结果后可再次请求调用，需设最大轮数防止死循环

tool_choice：调用控制策略

"auto"
默认值

模型自主判断是否需要调用工具。最常用的模式。

"none"
禁用模式

禁止模型调用任何工具，强制纯文本回答。

"required"
强制模式

必须调用至少一个工具，不能纯文本回答。

{ toolName }
精确模式

强制调用指定的某一个工具。

Zod：运行时类型守卫

为什么需要 Zod？

TypeScript 编译时

类型在运行时消失，any 数据直接通过

Zod 运行时

验证数据结构，保证类型安全

在 AI 场景中，模型返回的数据来自网络，属于 untrusted data。Zod 是最后一道防线。
import { z } from 'zod'; // 定义 Schema（同时获得 TS 类型） const TodoSchema = z.object({ id: z.string(), title: z.string() .describe('任务标题'), done: z.boolean(), dueDate: z.string().optional(), priority: z.enum([ 'high', 'medium', 'low' ]).describe('任务优先级'), }); // 自动推导 TS 类型 type Todo = z.infer<typeof TodoSchema>; // { id: string; title: string; // done: boolean; dueDate?: string; // priority: 'high'|'medium'|'low' } // 运行时验证 const result = TodoSchema.safeParse(data); if (result.success) { console.log(result.data); // 类型安全! }

Zod 常用 Schema 原语

z.string()

.min() .max() .email() .url() .describe()

z.number()

.int() .min() .max() .positive() .describe()

z.boolean()

布尔值：true | false

z.enum([...])

限定枚举值，AI 场景高频使用

z.object({...})

嵌套对象，支持多层结构

z.array(z.T)

同类型元素组成的数组

.optional()

字段可选，undefined 合法

.describe()

给 LLM 的描述提示，直接影响准确率

.default()

未提供时使用默认值

.describe() 会被 AI SDK 转为 JSON Schema 的 description，模型据此理解参数含义

Structured Outputs：结构化输出

让模型直接返回符合 Schema 的 JSON 对象，而非文本。

import { generateText, Output } from 'ai'; import { z } from 'zod'; const { output } = await generateText({ model: google('gemini-2.5-flash'), output: Output.object({ schema: z.object({ sentiment: z.enum([ 'positive', 'negative', 'neutral' ]), confidence: z.number() .min(0).max(1), keywords: z.array(z.string()), }), }), prompt: '分析这句话的情感', }); // output 类型自动推断为: // { sentiment: 'positive'|...; // confidence: number; // keywords: string[] }

Output 类型速查

Output.object() 返回结构化对象，最常用
Output.array() 返回类型化数组
Output.choice() 枚举选择，适合分类场景
Output.json() 任意 JSON，无类型保障
可组合：Tool Calling + Structured Outputs 可在同一次请求中使用。
